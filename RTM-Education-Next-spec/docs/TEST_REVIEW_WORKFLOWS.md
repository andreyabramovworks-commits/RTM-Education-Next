# Тесты, все попытки и проверка свободных ответов — общий workflow

Тесты используются как элементы курса и как полные тесты конкретной редакции статьи Базы знаний. Тест редакции создаётся в мастере, проходится после чтения статьи, хранит результаты по точному `article_revision_id` и может быть независимо скопирован в следующую редакцию с новым UUID. Оба вида используют одинаковые правила X/Y, свободных ответов, попыток и награды.

**Статус:** проверка через 2-й и 3-й разделы Центра проверок, двойной вариант возврата, аудит/попытки и меню всех действий утверждены. Детальная матрица полномочий и некоторые оценки требуют отдельного решения. Нет самостоятельного тестового пункта в Центре проверок.

## 1. Откуда открывается «Просмотреть ответы и попытки»

**Отдельная кампания:** `Центр проверок → Проверка отдельных материалов → материал-тест → кампания → сотрудник → Просмотреть ответы и попытки` (также из вида «По сотрудникам»).

**Тест в курсе:** `Центр проверок → Проверка курсов обучений → курс → кампания → сотрудник → раздел/элемент-тест → Просмотреть ответы и попытки`.

Обе точки ведут в **одну** полноценную страницу/широкое рабочее окно RTM (не узкая боковая панель). Заголовок/хлебные крошки показывают: тип контекста, сотрудника, название теста, ID конкретного назначения; есть `← Вернуться к сотруднику/курсу` с сохранением фильтров/скролла/раскрытых групп. Никакой самостоятельной 4-й вкладки.

## 2. Экран списка попыток (read-only просмотр)

Шапка: аватар/ФИО/отдел/должность сотрудника; тест, дата изменения, кампания/курс, срок, проверяющий, статус назначения, допустимое/использованное число полных попыток, сколько дополнительных выдано. Показать признак просрочки отдельно.

**Таблица попыток:** номер и ID попытки; начало, время отправки/закрытия; длительность и превышение time limit (если применимо); статус `in_progress/submitted/pending_review/returned/passed/failed/expired`; правильных автоматических X/Y; итоговое состояние; награда после сдачи; ответственное лицо; действия `Просмотреть попытку`, `Проверить` (при необходимости), `История`.

Сортировка по времени/номеру, выбранная попытка сохраняется при возврате. Исторические попытки **всегда отображать по сохранённому snapshot вопросов, выбранных вариантов и порядка на момент прохождения**, независимо от поздних изменений теста. Список должен включать старые неудачные попытки и исправления свободного ответа, а не только последнюю.

**Просмотр не меняет результат/награду и не требует подтверждения**. Доступ к чужим ответам проверяется backend; при необходимости фиксировать аудит доступа к чувствительным данным. Не выдавать в UI/ответ API правильные варианты, которые политика прохождения скрывает от ученика; преподавателю показывать по разрешённому праву.

## 3. Детальная страница отдельной попытки

Header `Тест / Попытка №n`, дата/время, статус, порог X/Y. Сводка: правильных автоответов X/Y, свободные ответы ожидают решения Принято/Не принято; итог Сдан/Не сдан/Ожидает проверки.

**Для каждого вопроса** показать: фиксированный текст, картинки/медиа/варианты в том порядке, который видел сотрудник; выбранный вариант или текст; факт правильности; для free-text — все версии отправленного текста, решение Принято/Не принято, комментарии, история возвратов и повторных отправок. При необходимости показывать, какой вариант был засчитан и почему (только проверяющему).

Ниже «История решений»: кто взял в работу, когда, кто проверил, какое решение принял, что вернул, причина, сколько попыток дополнительно выдал, когда ученик отправил исправление, что сделал администратор. Логи append-only; ручное подтверждение/освобождение не переписывает исходные баллы теста.

## 4. Проверка свободных ответов

1. Ученик завершает тест; сервер оценивает автоматические вопросы, свободные ставит `pending_review`; при непройденном X/Y фиксирует Не сдан без ручной проверки; при пройденном X/Y и свободных ответах фиксирует Ожидает проверки.
2. Создаётся **одна актуальная review-task** для данной отправки/попытки с `assignment_id`, `course_item_id` (для курса), `attempt_id`, `reviewer_scope`.
3. Проверяющий с правом открывает; может «Взять в работу». Операция **атомарная**: одновременный claim двумя людьми не даёт двух владельцев. Admin/developer может переназначать с причиной и аудитом.
4. На каждый свободный вопрос выбрать `Принять/Не принять` без числовой оценки, написать комментарий. **При возврате комментарий с конкретным исправлением обязателен**. Промежуточные проверки/комментарии сохранять как черновик, с version lock, без публичного результата.
5. «Завершить проверку» показывает итог, список оценённых/неоценённых вопросов, выбранный режим возврата и потенциальный результат теста. Сервер проверяет полноту обязательных оценок и актуальную версию записи.
6. Подтверждение фиксирует `review_actions`/`answer_reviews`, `reviewer_id`, time, решения по свободным ответам и число правильных автоматических ответов и audit; расчёт pass на сервере; ученик получает разрешённый результат/комментарий и, где уместно, уведомление.

## 5. ДВА режима возврата — выбор проверяющего

**A. «Исправить только свободный ответ» — утверждено.** Проверяющий отмечает конкретные free-text questions, пишет замечания, сохраняет `return_mode=answer_correction`. Ученик видит исходный ответ и комментарий, редактирует **только указанные ответы**, посылает новое содержимое. Сервер создаёт `answer_submission` с новым номером версии (старое не удаляет) и возобновляет проверку **в рамках той же полной попытки, без её расходования**. Старые автоматические ответы и факт их правильности остаются неизменными. Циклов исправления может быть несколько до принятия. Каждый возврат открывает отдельное окно исправления: число суток настраивается у теста, по умолчанию 7; после срока отправка закрыта. Общий таймер первоначальной полной попытки после её отправки не возобновляется. Новый возврат — новое решение преподавателя и новое окно; полная пересдача остаётся отдельным действием. `REQ-178`, ADR-091.

**B. «Пройти тест заново» — утверждено.** Проверяющий указывает `return_mode=full_retake`, пишет комментарий. Предыдущая попытка фиксируется и остаётся в истории. Ученик начинает *новую* полную попытку (номер +1), если есть лимит/выдан дополнительный allowance. Система не переносит old answers или старый scoring в новую попытку.

**При возврате преподаватель выбирает вариант сам**. Нельзя автоматически расходовать новую попытку для исправления ответа или наоборот автоматически разрешать только частичный возврат. Если попыток не осталось, действие выдачи попыток — отдельная операция с правами.

## 6. «Выдать дополнительную попытку»

Окно с названием теста, сотрудником/назначением, базовым лимитом, использовано/доступно, выдано ранее, полем `+N попыток`, обязательной причиной, кнопками «Отмена»/«Подтвердить». Система создаёт immutable allowance для **конкретной активности/назначения**, не меняет исходный `test_definition.max_attempts`, другие курсы или других людей. Audit actor/time/reason/количество. Проверять, что текущая попытка не выполняется одновременно и нет конфликтных grants. Старые попытки не удалять.

## 7. Действия сотрудника: рекомендованное + «Все действия»

Обязательно показывать **одно наиболее уместное основное действие**, но рядом постоянно доступное меню **«Все действия»** со всем, что позволяет роль/область: `Просмотреть ответы и попытки`, `Проверить свободные ответы`, `Напомнить`, `Изменить срок`, `Выдать попытки`, `Освободить от прохождения`, `Подтвердить вручную`, `История`. Не завязывать доступ только на текущую подсказку системы.

| Операция | Подтверждение/диалог | Побочный эффект |
|---|---|---|
| Просмотреть ответы и попытки | Нет, если только чтение | Нет мутаций; доступ проверяется сервером |
| Проверить | Черновик → сводка → подтверждение | Запись оценок, решение, audit, worker уведомление |
| Напомнить | Кому/как, подтвердить | Создать задачу worker, статус доставки не угадывать |
| Изменить срок | Новый дедлайн, причина, подтвердить | Изменить только одно назначение; audit |
| Выдать попытку | N, причина, подтвердить | Grant только конкретному activity; audit |
| Освободить | Обязательная причина, повышенное подтверждение | `exempted`; **не** `passed`; audit |
| Подтвердить вручную | Обязательная причина, повышенное подтверждение | `manual_completed`, не фальсифицировать тестовые баллы; audit |
| История | Только просмотр | Нет мутаций |

Недоступные операции можно показывать disabled с понятным текстом; окончательный серверный отказ остаётся обязательным. Для некоторых операций точная матрица ролей **OPEN**, безопасное ограничение до её согласования.

## 8. Сохранность и защита от гонок

- Уникальная отправка создаёт одну текущую review-task, дубликаты кнопки / retry не плодят задач.
- Для claim и изменения оценки — conditional update по `row_version`; если кто-то проверил раньше, UI сообщает о конфликте и предлагает загрузить новое состояние, не перезаписывает.
- Каждая версия ответа, каждый `review_action`, каждое пересчитывание оценки/срока и `attempt_allowance` — отдельная долговечная запись с ID, actor, time, reason, linked attempt/answer.
- Скрытые правильные ответы только в backend; серверный таймер и лимиты попыток; не считать «видео просмотрено» без достоверного источника события.
- Обработчик UI отменяет предыдущий запрос при выборе иной попытки, показывает загрузку/ошибку/отсутствие прав.

## 9. Приёмка

T01. Открытие старой попытки после изменения живого теста показывает снимок первоначальных вопросов/вариантов в правильном исходном порядке.
T02. У учителя с правом просмотра все попытки доступны, без права — 403 и нет утечки через export.
T03. Read-only «Просмотреть ответы и попытки» без предупреждения «Вы уверены?» и без изменения данных.
T04. Два преподавателя одновременно claim → лишь один успешен; второй получает причину/свежие данные.
T05. Free-text correction меняет только версию свободного ответа, **не увеличивает attempt_no**.
T06. Full retake увеличивает attempt_no на 1, сохраняет прежнюю попытку, учитывает лимит и индивидуальные grant.
T07. Переход из двух разных вкладок открывает **тот же** механизм проверки, но сохраняет breadcrumb/back context.
T08. Возврат без комментария о причине блокируется.
T09. Пока обязательная ручная проверка pending, пользователь не получает преждевременный окончательный pass/fail.
T10. Основное действие не скрывает меню «Все действия», permissions проверяются backend.
T11. Преподаватель может сохранять черновик оценки, выйти и вернуться без потери незафиксированного решения.

## Порог X/Y и награда за сдачу

Тест сдан, не сдан либо ожидает проверки. Сервер считает правильные автоматические ответы, каждый вопрос верен или неверен; multiple-choice требует точного совпадения набора. Порог — X из Y, например 5/6. Баллов за вопросы и частичных баллов нет. При непройденном автоматическом пороге — не сдан, попытка использована, свободные ответы не идут на ручную проверку. При пройденном пороге и свободных ответах — ожидает проверки; все обязательные ответы должны получить «Принято» от преподавателя. Числовой оценки свободного ответа нет. Частичное исправление остаётся в той же полной попытке; полная пересдача требует новой. Начатая попытка сохраняет снимок вопросов, новая берёт текущий тест. Баллы начисляются только как награда за весь тест после итогового «Сдан»; при failed/pending_review награды нет. Размер награды настраивается у теста; ledger с уникальной парой назначение–тест предотвращает повторное начисление при дополнительных попытках и исправлениях. Новая кампания создаёт новое назначение. `REQ-177`, ADR-092. Тест только со свободными ответами OPEN-037. MVP типы: один вариант, несколько, свободный текст; изображения поддержаны, matching/sequence отложены.
