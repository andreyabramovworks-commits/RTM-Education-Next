# Курсы — программа, внутренние статьи и тесты

**Статус:** базовые функции и рабочие правила приняты пользователем 23.11.2026. Визуальный дизайн, тонкая схема навигации, некоторые варианты drag & drop — проектная детализация, не готовый интерфейс.

## 1. Административный раздел «Курсы» — каталог

Самостоятельной вкладки «Материалы» **нет**. Один рабочий раздел «Курсы» содержит самостоятельные курсы, в которых живут собственные статьи и тесты.

Шапка: «Курсы», поиск по названию/описанию, основная кнопка «Создать курс», сортировка. Главный вид — **таблица**, а не сетка больших карточек. Предлагаемые колонки: название/краткое описание, дата изменения, статус (черновик/опубликован/архив), состав (число разделов/статей/тестов/Google Docs/видео), режим прохождения, активные кампании, автор, обновлено, «Открыть» + «Все действия».

Фильтры: статус, автор, дата изменения, режим последовательный/свободный, поиск. При открытии курса и возвращении сохранять фильтр, сортировку, страницу, положение прокрутки. Недоступные права отражаются в UI и backend.

Действия строки: открыть, предпросмотр, создать копию курса с независимыми статьями/тестами, история, кампании/назначения, архивировать. Не пытаться автоматически дублировать результаты учеников.

## 2. Страница курса — основные области

Навигация: `Курсы / Название курса`; подзаголовок текущее состояние, статус черновика, индикатор сохранения. Внутренние шаги **«Описание» → «Программа» → «Предпросмотр»**. После публикации — действие «Назначить обучение», открывающее отдельный мастер кампании (см. `COURSE_ASSIGNMENTS.md`). Курс целиком открывается как полноценная страница, не тесная модалка.

### «Описание» — поля

- Название (обязательно); цель; краткое и развёрнутое описание; возможная необязательная обложка курса (UI-предложение).
- Режим прохождения: **свободный** / **последовательный**; для последовательного следующий обязательный элемент доступен после необходимых условий предыдущего.
- Настройка общих правил завершения; статус и информация об авторе/создании/редакции. Номер и дата фиксируются при публикации.
- «Сохранить черновик», «Перейти к программе», «Предпросмотр»; явное сообщение об ошибке автосохранения.

### «Программа» — разделы и сортировка

- Структура `Курс → Раздел 1, Раздел 2, ... → элементы`. У каждого раздела заголовок, позиция, кнопки «Переименовать», «Добавить элемент», «Переместить», «Удалить из черновика». Вложенные уровни секций сверх одного — не подтверждены пользователем; если потребуются, спросить.
- Создать **новый раздел**, изменить имя, переставить целый раздел относительно соседних, удалить/переместить его элементы при удалении по явному выбору — подтвердить безопасное поведение.
- У элемента: номер в разделе, тип с понятной иконкой, название, необязательное описание, дата изменения, обязательный/необязательный, правило завершения, статус сохранения, меню действий. Кнопки/метки доступны с клавиатуры.
- **Drag & Drop мышью:** свободно переставить элемент в пределах раздела; перенести в другой раздел, который раскрыт/виден; менять порядок разделов. Сохранять результирующую последовательность в черновике на сервере. При неудачном сохранении показывать ошибку и возможность повторить; не «терять» элемент. Отдельных команд перемещения вверх/вниз или в другой раздел в меню нет; перенос выполняется мышью за ручку строки.
- Перестановка обновляет живой курс; выполненные действия и завершённые результаты остаются историчными, незавершившие при следующем открытии видят новый порядок.
- Клик на строку элемента: статья → **полноценный Tiptap редактор** со встроенными Google Docs/медиа; тест → **полноценный конструктор**. Не открывать тесный боковой drawer.
- Из каждого элемента постоянная кнопка/ссылка **«← К программе курса»**. При возврате сохранить курс, текущее состояние, раскрытый раздел, прокрутку, поиск/фильтры, несохранённый ввод. Если черновик не успел сохраниться, показать предупреждение/повтор, не молча потерять.
- **«Добавить элемент курса»** открывает: `Создать статью`, `Создать тест`, `Копировать статью/тест из другого курса`. Google Docs, видео и аудио вставляются в тело статьи.

### «Предпросмотр»

Показать сценарий сотрудника в выбранном режиме свободного/последовательного прохождения: список разделов/элементов, правила разблокировки, кнопки/прохождение статьи, тестовый экран, in-app документ/видео; не создавать реальные попытки, результаты, уведомления или назначения при preview. Права preview для редактора, админа, разработчика. Можно вернуться к конкретному элементу редактирования.

## 3. Создать и редактировать статью внутри курса

Путь: `Курсы → Курс → Программа → Добавить элемент → Создать статью` либо щелчок по уже созданной статье. **Полноценная страница**, breadcrumbs с именем курса/раздела/статьи, «← К программе курса», «Сохранить черновик», «Предпросмотр», статус сохранения, доступ к истории.

| Поле | Назначение |
|---|---|
| Название | Заголовок статьи; обязателен для публикации |
| Краткое описание | Что изучит сотрудник |
| Обложка | Необязательное превью в списке курса |
| Содержание | Tiptap JSON, серверная валидация и безопасный рендер |
| Обязательность | Участвует ли элемент в завершении курса |
| Подтверждение | Требуется ли подтвердить изучение; варианты кнопка / один вопрос / связанный полный тест через согласованный механизм |
| История | Техническая история правок и снимков, без пользовательских редакций курса |
| Метаданные | Автор, дата создания, статус автосохранения |

Тулбар собственной сборки на открытом Tiptap: параграфы/заголовки, жирный/курсив/подчёркивание, списки, ссылки, таблицы, изображения, выделенные блоки, медиа и контролируемые embeds; платные зависимости не использовать, Excalidraw полностью исключить. Поддерживать undo/redo, предсказуемое выделение, безопасный paste. Содержание хранится на сервере в JSONB с format_version; изображения в защищённом файловом storage и ссылками на asset.

**Черновик:** серверное автосохранение после ввода и явно вызываемое «Сохранить», понятное «Сохраняем.../Сохранено/Ошибка»; при offline/ошибке запрет молчаливой потери текста; подтверждение выхода при unsaved. Предпросмотр идентичен тому, что увидит ученик, без фактического подтверждения. Статья изменяется с сохранением истории и снимков уже показанного содержания.

**Копирование:** в другом курсе `Программа → Добавить элемент → Копировать из другого курса`, поиск по курсам/статьям/тестам, предпросмотр источника, подтвердить «Создать копию». Новый UUID статьи, собственное текущее содержание, копия Tiptap JSON/asset reference согласно политике storage, отдельный `copied_from_article_id` для аудита. Не делить mutable контент. Старые ответы/назначения/результаты не копировать.

## 4. Создать и редактировать тест внутри курса

Путь: `Курсы → Программа → Создать тест` или щелчок теста; **полноценный конструктор на отдельной странице** и «← К программе курса».

Разделы формы:

1. **Основное:** название, краткое описание, необязательная обложка/изображения, обязательность для курса, дату изменения, статус черновика.
2. **Вопросы:** добавить вопрос, выбрать тип (`single` — один правильный; `multiple` — несколько; `free_text` — свободный), написать формулировку, добавить изображения/медиа, варианты/правильные ответы (только backend для ученика), обязательность; дублировать/удалить/перетащить вопрос, менять порядок вариантов.
3. **Настройки теста:** лимит времени, количество полных попыток, минимальное количество правильных автоматических ответов X/Y, перемешивание вопросов/вариантов, доступность результатов и правильных ответов после завершения, server-side timer.
4. **Ручная проверка:** вопросы с проверкой преподавателем, критерии, решения Принято/Не принято, комментарии, варианты возврата: исправить свободный ответ без списания попытки ИЛИ повторить весь тест.
5. **Предпросмотр:** проверка глазами сотрудника без реальных попыток; ошибки в вопросах и неуказанный правильный ответ блокируют публикацию.

Сервер считает правильные автоответы; преподаватель принимает или отклоняет свободные ответы. Награда баллами начисляется только после итогового «Сдан». Если авто-порог не пройден, результат «Не сдан» без ручной проверки. Исторический снимок вопросов/порядка/ответов каждой попытки сохраняется. Копирование теста между курсами — полный независимый тест и вопросы/правила с новыми идентификаторами; **без** попыток/результатов.

Matching/sequence не входят в MVP.

## 5. Добавить Google Docs в статью курса

Штатный путь: `Программа → статья → редактор Tiptap → вставить Google Docs → выбрать зарегистрированный материал`. Поиск, название, идентификатор и предпросмотр доступны в диалоге. Блок внутри статьи показывает актуальное содержимое Google Docs при открытии страницы. Прямой новый Google URL в редакторе курса не вводится; регистрация источника происходит в Базе знаний. Google Docs не является отдельной строкой программы.

## 6. Добавить видео и аудио в статью MVP

`Программа → Статья → Вставить медиа`: видео по RUTUBE либо загрузка MP4/WebM/MOV, аудио загрузкой MP3/WAV. У блока название/описание и внутренний плеер; ошибка загрузки или воспроизведения видна. Файлы хранятся на сервере с проверкой доступа. Вставка не создаёт отдельной строки программы курса.

## 7. Общее поведение элементов и курса

- Каждый элемент курса находится в разделе и позиции; required flag меняется в живом курсе; завершённые результаты остаются.
- Каждое действие, возможное пользователю, доступно через главное действие + контекстное меню «Все действия» там, где это уместно. Права backend при всех мутациях.
- Публикация **явная**: `Сохранить черновик` ≠ `Первично активировать курс` ≠ `Назначить обучение`.
- Публикация проверяет заполненность названия, разделов/элементов, валидность ссылок, доступность контента, тесты, условия последовательности и актуальность Google Docs. Не создавать частично опубликованную программу.
- Курс редактируется до, во время и после кампаний с сохранением исторических снимков. Прогресс независим для каждого назначения даже при похожих элементах в нескольких курсах.
- Режимы успешной загрузки, пустого списка, ошибки, недостатка прав, offline/сети, отсутствующего внешнего источника, конфликтного редактирования — обязательны для UX.

## 8. Проверяемые пользовательские сценарии

C01. Создать курс → задать цель/описание/режим → сохранить черновик → открыть программу.
C02. Создать два раздела; добавить в один статью и тест; DnD тест во второй; изменить порядок разделов; refresh → порядок сохранён.
C03. Щелчок статьи → полная страница Tiptap, ввод/автосохранение, preview; возврат в исходный раскрытый раздел со сохранённой прокруткой.
C04. Щелчок теста → полный конструктор, настройка вопросов/порога X/Y/таймера; preview; возврат в программу.
C05. Вставить Google Docs из БЗ блоком статьи, показать актуальное содержимое внутри RTM и вернуться в курс. Отдельного Google Docs элемента программы нет.
C06. Вставить RUTUBE URL; встроенное видео preview; плохая/закрытая ссылка показывает понятное состояние; возврат.
C07. Скопировать статью/тест из иного курса → новый UUID/ревизия, редактировать копию → оригинал неизменен.
C08. Изменить живой курс при активной кампании; незавершившие видят актуальное, завершённые результаты сохраняются.
C09. Потеря сети во время автосохранения не выдаётся за «Сохранено», пользователь не теряет текст.
C10. Опубликовать курс отдельно от запуска кампании; не создавать assignments по факту save/publish.
C11. После публикации запустить мастер назначения с выбором отделов/людей и Bitrix настроек (см. COURSE_ASSIGNMENTS).

## Согласованный UX программы курса, 23.11.2026

Каталог — таблица с поиском, фильтрами, сортировкой, составом, статусом, автором, датой, редакцией и активными назначениями. «Открыть» — главное действие; возвращение восстанавливает страницу, фильтры и прокрутку. Полноценная страница курса: возврат, цепочка, название, дату изменения, статус, состояние сохранения, «Сохранить черновик», «Предпросмотр», «Сделать курс доступным для назначения». Области: «Описание», широкая одноколоночная «Программа», «Предпросмотр». Предпросмотр не создаёт попыток, результатов и назначений.

Структура строго `курс → раздел → материал`; вложенных подразделов нет. «+ Раздел» создаёт именованный раздел; разрешены переименование, сворачивание, разворачивание и перенос целого раздела с содержимым. При удалении заполненного раздела диалог показывает число материалов и выбор: удалить раздел вместе с элементами только из редактируемой программы либо перенести элементы в выбранный другой раздел в исходном порядке. Требуется подтверждение; при отсутствии другого раздела перенос недоступен. История назначений и результатов сохраняется.

Drag & Drop мышью начинается только за отдельную ручку. Название открывает материал. Можно менять порядок внутри раздела, переносить в другой, включая пустой и свёрнутый (цель удобно раскрывается), менять порядок разделов. Отмена до отпускания не меняет данные. Перенос не копирует материал и не меняет UUID. Порядок сохраняется на сервере; ошибка видна, материал не теряется и не дублируется.

«Добавить элемент» предлагает создать статью, создать тест либо скопировать статью/тест из другого курса. Строка показывает тип, название, дату изменения, состояние, обязательность и разрешённые действия. Клик на название ведёт на полноценную страницу статьи Tiptap либо конструктора теста. Внутри статьи можно вставлять текст, таблицы, несколько Google Docs, видео и аудио в любом порядке. Везде есть «К программе курса» с восстановлением курса, раздела, раскрытия, прокрутки и черновика.

Статья: название, описание, необязательная обложка, содержание, обязательность, способ подтверждения, дату изменения, описание изменений, автор, даты, состояние сохранения. Открытый Tiptap MIT: заголовки, абзацы, жирный/курсив/подчёркивание, списки, ссылки, таблицы, изображения, выделенные блоки, управляемые встраивания, undo/redo. Серверное автосохранение и явное сохранение; статусы «Сохраняется», «Сохранено», «Ошибка»; выход при ошибке не теряет текст молча. Предпросмотр без подтверждения.

Тест: полноценные области «Основное», «Вопросы», «Настройки», «Проверка», «Предпросмотр». Вопросы добавляются, меняются, удаляются, копируются и сортируются. Базовые типы: один вариант, несколько, свободный текст; изображения в вопросах/ответах. Настройки: время, попытки, порог X/Y правильных автоматических ответов, перемешивание, показ результата/ответов. Сервер оценивает закрытые ответы; свободный ответ требует преподавателя до итогового результата. При возврате преподаватель выбирает исправление только ответа без новой полной попытки либо повтор всего теста с доступной/выданной попыткой. История ответов, исправлений, баллов и решений сохраняется.

Google Docs выбирается для блока статьи из каталога Базы знаний; прямой URL в курсе отсутствует. Статья хранит ссылку на материал Google Docs и показывает актуальное содержимое при открытии. Видео в MVP: RUTUBE или файл MP4/WebM/MOV на сервере; аудио MP3/WAV на сервере. Оба типа добавляются блоком статьи и воспроизводятся внутри RTM. Ошибка воспроизведения видна; открытие страницы не доказывает полный просмотр.

Копирование: выбрать курс и статью/тест, просмотреть и создать независимую копию с новым UUID, содержимым/вопросами и собственным содержимым; результаты/ответы/назначения не копировать. Копируется текущее сохранённое содержимое, включая черновик при наличии доступа.

После активации доступны назначение и редактирование живого курса независимо от кампаний. Сохранение, первая активация и запуск кампании отдельны. Некорректный тест и незаполненные обязательные данные блокируют активацию; пустой раздел, временно недоступный Google Docs и RUTUBE дают предупреждение с «Отмена»/«Продолжить» и аудитом. Несохранённый черновик предлагает сохранить или отменить действие без отката ввода. Точная семантика первой активации OPEN-040.

Конкурентное редактирование использует версию записи: устаревшая запись не перезаписывает свежую молча. Админка рассчитана на компьютер; мобильная пользовательская часть доступна.

## Живой курс и копирование

Курс, собственные статьи и тесты имеют постоянные UUID и текущее редактируемое содержание; пользовательских редакций у них нет. Редактор меняет их до, во время и после кампаний с предупреждением о влиянии значимых изменений на незавершивших. Статья или тест копируется из текущего сохранённого состояния, включая доступный черновик, с новым UUID и без истории результатов. «Создать копию курса» создаёт новый черновик со структурой, правилами и независимыми статьями/тестами; ссылки внутри блоков могут указывать на те же зарегистрированные Google Docs, но сами статьи остаются независимыми. Кампании и назначения не копируются.
