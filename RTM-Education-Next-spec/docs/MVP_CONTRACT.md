# Контракт MVP — что именно должно работать и как проверять

**Утверждено для MVP:** курсы; статьи Базы знаний и курса; единые папки и ACL Базы знаний; редакции статей, обновления и тесты редакций; встроенные Google Docs, RUTUBE, серверные видео/аудио; Центр проверок из трёх вкладок, Bitrix24 и роли. **Отложено:** рабочая вкладка «Требует действий», просмотр завершённых кампаний, должностная матрица. **Открыто:** формат исходной таблицы для однократного импорта (`OPEN-042`).

## Админ-экраны MVP

| Экран | Что делает | Права и проверки |
|---|---|---|
| Курсы — каталог | Таблица курсов, поиск/фильтр, создать, открыть, история изменений, статус/активные назначения | teacher читает и назначает любому сотруднику, editor+ меняет; сохранить позицию |
| Курс → Описание | Название, цель, описание, свободный/последовательный режим, draft | Изменение только editor+; auto-save на backend |
| Курс → Программа | Разделы, DnD внутри/между разделами, обязательность, тип и актуальное состояние элемента | Живой курс изменяем; валидировать перестановки и сохранять историю выполненных действий |
| Курс → Статья | Полноценная Tiptap страница с текстом, таблицами, Google Docs, видео, аудио и preview | Без пользовательских редакций; autosave и возврат |
| Курс → Тест | Полный конструктор single/multiple/free, баллы, медиа, attempts, timer, pass, preview | Correct answers backend, старые попытки неизменны |
| Курс → Предпросмотр | Просмотреть путь ученика и блокировки, вернуться к редактору | Не создаёт реальные результаты и кампании |
| Курс → Назначить обучение | Отделы/дочерние/люди, ответственные, сроки, уведомление/задача Bitrix independently, редактируемые название/описание и preview, запуск | One assignment/user/campaign; backend + durable job |
| Управление редакциями | Датированные редакции целых статей БЗ, снимки Google Docs, режимы ознакомления, полные тесты, кампании | Не потерять историю и audit; одна дата/одна редакция |
| Центр → Требует действий | Только плашка «появится позже» | Никакой фальшивой очереди |
| Центр → Отдельные материалы | Активные кампании, по материалам/сотрудникам, фильтры/группировки, stats, full-page карточка, действия, ответы/попытки | Correct scope, CSV/XLSX, review engine |
| Центр → Курсы обучений | Активные кампании, по курсам/сотрудникам, прогресс, full-page карточка, тесты/попытки | Постоянный course ID, снимки истории, прогресс только по обязательным элементам |
| База знаний (админ) | **Одна** вкладка, единое дерево папок, статьи, ACL, импорт Google Docs, загрузка видео и аудио | Backend проверяет доступ к статье, папке и файлу |
| Сотрудники и роли | Bitrix24 sync, пользовательские роли и server-scoped админка | auto-Bitrix-admin, protected developer |

## Обычный пользователь — MVP

- Входит через Bitrix24; видит «Обучение → Курсы/Обновления», разрешённую Базу знаний и Профиль.
- Открывает курс или назначенное обновление, читает статьи с встроенными Google Docs, RUTUBE, серверным видео и аудио, выполняет подтверждения/тесты. Последовательная программа блокирует следующие шаги, пока условия предыдущих не выполнены.
- Видит сроки, количество попыток/остаток, прогресс, промежуточное состояние «На проверке»; после review — комментарий, результат, возврат только текста или новый полный тест согласно решению преподавателя.
- Не видит чужих персональных результатов и неподходящих ему документов.
- База знаний показывает разрешённые папки и статьи; прямые ссылки и медиапотоки проверяются сервером.

## Механизмы результатов

- Подтверждение обновления связывать с точной редакцией статьи БЗ; подтверждение внутренней статьи курса — со стабильным ID и техническим снимком показанного содержания.
- Тест: server-side grading, лимиты попыток и времени, свободные ответы с ручной проверкой, порог X/Y, история и награда только за итоговое Сдан, коррекции без доп попытки, полная пересдача как новая попытка.
- Отдельные назначения и курсовые активности не делят прогресс автоматически. Внутри курса результаты на фиксированных course_item IDs.
- Преподаватель видит главное релевантное действие **и** меню всех разрешённых действий. Просмотр попыток без изменения данных, изменения с подтверждением и audit.

## Отложенные экраны, **не реализуем как действующие в MVP**

- Постоянная синхронизация папок и должностной матрицы из Google Sheets не входит в MVP; первичный импорт Google Docs выполняется однократно.
- Рабочая очередь «Требует действий»: оставить текстовую плашку.
- «Завершённые кампании» в обоих подразделах Центра проверок: оставить placeholder, а не фальшивую статистику.
- Автоматический перенос успешного результата между разными курсами.
- Инструменты Excalidraw и платные компоненты Tiptap.

## Границы реализации

**Пользователь утвердил концепцию БД, а не каждую SQL-колонку;** до DDL уточнить OPEN_QUESTIONS. Backend авторизация не может опираться только на скрытые кнопки. Самопроизвольный push/commit/tag, изменения production и правки старого `/opt/rtm-app` запрещены.

## Основные критерии готовности

- Сквозной сценарий: создать курс → статью и тест → перетащить тест между разделами → preview → первично активировать курс → назначить отдел/людей → Bitrix task/уведомление по переключателям → ученик проходит → преподаватель проверяет free-text → результат и прогресс → аудит.
- Google Docs выбирается из БЗ блоком статьи, внутри RTM показывает актуальный текст; при выпуске редакции БЗ сохраняется исторический текстовый снимок.
- Тестовые материалы созданы внутри курса, скопированный тест имеет **отдельные ID и изменения**.
- Прошлые редакции статей БЗ и завершённые прохождения не меняются от новых публикаций и правок живого курса.
- Две вкладки контроля показывают правильную активную кампанию и только разрешённые данные; первая только информирует о future.
- Экспорт CSV/XLSX реален, гонки запросов/конкурентных review исключены и проверены.
- Реальный Bitrix outage не разрушает назначения и не создаёт дублирующие задачи при повторе.

## Программа курса и публикация, уточнение 23.11.2026

Админка курса предназначена для компьютера; мобильная пользовательская часть работает. Редактор и выше создаёт и публикует курс; преподаватель и выше создаёт назначения любому сотруднику компании, не редактируя контент. Google Docs находится блоком статьи курса. Живой курс меняется до, во время и после кампаний; исторические результаты защищены снимками. Пустой раздел, временно недоступный Google Docs и невоспроизводимое RUTUBE-видео дают предупреждение с явным «Продолжить» и аудитом; некорректный тест, пустой курс/статья и отсутствие выбранного документа блокируют. Сохранение, публикация и назначение раздельны.

## Приоритет окончательного согласования 23.11.2026

Курс и внутренние статьи/тесты не имеют пользовательских редакций; изменения разрешены при активных и завершённых кампаниях. Кампании курса ссылаются на постоянные ID, кампании обновлений — на точную редакцию статьи БЗ. Тест проходит по X/Y правильных автоматических ответов; свободные ответы принимаются или отклоняются без числовой оценки. Баллы начисляются только как награда после итогового «Сдан». Преподаватель работает с любым сотрудником компании, контент редактирует редактор и выше.
