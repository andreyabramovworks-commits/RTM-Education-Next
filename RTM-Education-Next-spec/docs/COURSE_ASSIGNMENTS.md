# Назначения курсов, кампании и интеграция Bitrix24

**Статус:** основные возможности и мастер назначений подтверждены пользователем 23.11.2026. Место входа: активированный курс → «Назначить обучение». Кампания **не запускается** при сохранении черновика или первой активации курса.

## Объекты и контекст

- Есть `course_id` — постоянный ID изменяемого курса.
- Кампания обновления ссылается на точный `article_revision_id` статьи Базы знаний; публикация редакции сама не создаёт назначения. У пользователя назначение находится в «Обучение → Обновления».
- Есть `assignment_campaign` — массовое правило «кому/кто проверяет/когда/куда отправить», состояние draft/active/closed, автор запуска, дата.
- Есть индивидуальное `assignment` — сотрудник, кампания, живой курс, дата/срок, реальный статус, собственный прогресс.
- У одного сотрудника могут быть разные назначения курсов и отдельные кампании; учебная активность и результаты **не переносятся между ними автоматически**.
- Мастер получателей, сроков, ответственных и Bitrix применяется и к кампаниям обновлений статей; тест редакции завершается после чтения статьи и использует общий движок попыток/проверок.

## Мастер «Назначить обучение» — шаг за шагом

### 1. Получатели

Дерево подразделений Bitrix24 со вложенностью; выбор отдела целиком и настройка включения подотделов; выбор отдельных сотрудников поиском по ФИО/ID/должности, возможно «все активные». Перед запуском — количество уникальных получателей и список исключённых дублей/неактивных. Один сотрудник в нескольких выбранных отделах получает **одно** назначение кампании. Есть согласованное ранее расширение «учитывать новых сотрудников»: динамический подбор после запуска и безопасное создание назначения по правилам, без дублей (точные граничные сроки/исключения уточнить).

### 2. Ответственные за проверку

Выбор одного или нескольких преподавателей/ответственных определяет маршрутизацию ручных ответов и напоминаний, а не ограничивает утверждённое право роли преподавателя работать с любым сотрудником компании. Если ответственного нет, fallback admin — **PROPOSED**, не закреплять скрыто.

### 3. Сроки

Два подтверждённых режима: **относительный** срок (например, N календарных дней после индивидуального назначения) или **абсолютная** дата для всей кампании. Показать часовую зону и момент окончания. Срок курса отличается от лимита времени прохождения отдельного теста. Изменение дедлайна для одного сотрудника не меняет все назначения; любые исключения с actor/reason/audit. Правило перерасчёта сроков уже активной кампании (`new_only` / `recalculate`) в legacy присутствует, бизнес-выбор для Next уточнить.

### 4. Уведомления и задачи

Два **независимых** переключателя: `Отправить уведомление` (Bitrix24/in-app — точная конфигурация позже) и `Создать задачу Bitrix24`. Для задачи редактируемые **название и описание**; поля-шаблоны для курса, ФИО, даты/срока, ссылки; предпросмотр реальной задачи до запуска. Дедлайн задачи связан с назначением. Предусмотреть настройку включения/выключения эскалации руководителю и повторных напоминаний, как в старой кампании; точные интервалы/правила не утверждены. Не вставлять секреты в шаблоны.

### 5. Подтвердить и запустить

Сводка: название и текущий состав курса, количество уникальных сотрудников, подразделения/отдельные люди, ответственные, политика дат, уведомления on/off, задачи on/off, предварительный просмотр заголовка/описания задачи. Кнопки «Назад», «Сохранить черновик кампании», «Запустить обучение»; явное подтверждение запуска массовой операции.

В одной DB-транзакции зафиксировать кампанию, персональные назначения, ID курса и записи jobs в durable queue. Worker доставляет сообщения/задачи и повторяет временные сбои; не дублирует назначение. Результат API: назначения сохранены, доставка `pending/partial/sent/failed` по факту, нельзя ложно показывать «задачи успешно созданы» до подтверждения Bitrix.

## Действия после запуска

Открыть список назначенных, уточнить получателей/ответственных, вручную добавить сотрудников, изменить срок для будущих или текущих назначений с выбором политики, переключить включение новых сотрудников, при необходимости повторить неудачную доставку. Отправить напоминание, изменить срок/выдать попытку отдельному сотруднику, освободить с причиной или подтвердить вручную с повышенным правом — из Центра проверок. Завершённые/освобождённые назначения не изменять задним числом. Закрытие кампании не должно уничтожать историю.

## Данные и идемпотентность

- Правила получателей храним версионированно как JSONB-policy + явные разрешённые типы; конкретные назначения — отдельные строки FK.
- Уникальность `(campaign_id, user_id)`; idempotency keys для launch и job; защищённый от повторов retry.
- Сохранять `assigned_at`, `available_from`, `due_at`, `started_at`, `completed_at`, `status`, `closed_at?`, override reason, creator, `course_id`, `recipient_source`, `delivery_state` через интеграционные записи.
- Для исторического отчёта важно помнить, какой департамент/правило дало назначение, даже если человек перешёл в другой отдел.
- `is_overdue` лучше выводить из due + effective status, сохраняя отдельную отметку, когда просрочку зафиксировали; не подменять `completed`/`pending_review` одной строкой `overdue` без пояснения.

## Приёмка

A01. Один сотрудник в двух отделах → одно назначение на кампанию.
A02. Изменение курса после launch не меняет состав уже выданных заданий.
A03. Уведомление off / задача on → создаётся только задача, и наоборот.
A04. Название/описание задачи реально совпадает с preview после подстановок.
A05. Временная ошибка Bitrix → назначение сохранено, job на повтор, явная ошибка доставки.
A06. Новичок, попавший под правило, получает назначение один раз; повтор sync без дублей.
A07. Преподаватель и выше может назначить доступный курс любому сотруднику компании и изменить срок конкретного назначения; backend проверяет роль, объект и обязательные причину/аудит для рискованных действий.

## Право запуска

Преподаватель и выше открывает мастер доступного курса и создаёт назначения любому сотруднику компании. Предварительная проверка уникальных получателей, ответственных, относительного/абсолютного срока, независимых переключателей уведомления/задачи Bitrix24, редактируемых названия и описания задачи, подстановок и preview обязательна. Массовый запуск подтверждается; worker повторяет доставку без дублей назначений.

## Живые кампании

Кампания ссылается на постоянный UUID курса; отдельная кампания статьи/теста — на существующий материал без копии. Прохождения независимы. Статусы кампании: черновик, активна, успешно завершена, закрыта с исключениями, закрыта без полного выполнения, отменена. Просрочка не закрывает кампанию. При динамическом наборе закрытие возможно лишь по завершении периода набора. Закрытие не блокирует правку курса. Статусы назначения: не приступил, в процессе, ожидает проверки, возвращено, завершено, освобождён, отменено. Освобождение не равно прохождению. Незавершивший видит актуальные обязательные элементы; завершивший сохраняет результат. Напоминания: за 2 дня, в день срока, через 3 дня; эскалация руководителю через 7 дней выключена по умолчанию. Повтор worker не дублирует доставку.
