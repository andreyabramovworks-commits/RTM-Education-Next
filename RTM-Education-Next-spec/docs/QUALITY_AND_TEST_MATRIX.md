## Процедура приёмки Work

Для каждого изменённого документа/функции: выбрать требования из `REQUIREMENTS_TRACEABILITY.md`, проверить их против согласованных ADR, построить соответствующий pytest/Vitest/Playwright сценарий, выполнить его на реально работающей сборке, указать PASS/FAIL/BLOCKED с доказательством. **Плановый тест не равен выполненному тесту**. Релизный smoke + health/readiness + DB migration обязательны перед утверждённым production release.
