# Архитектура приложения — системный контракт

**Статус:** архитектура и стек согласованы на концептуальном уровне. Названия отдельных таблиц, индексные стратегии и точная схема API — рабочие предложения, не DDL.

## Компоненты

`Bitrix24 (identity/оргструктура/уведомления/задачи)` ↔ `FastAPI (серверные сессии, RBAC, учебная логика, API)` ↔ `PostgreSQL 17`. Браузер: `React 19 + Vite + TypeScript` SPA. Редактор — `Tiptap MIT + custom UI`, **Excalidraw исключён**. Фоновые задачи в отдельном Python worker, PostgreSQL queue. Google Drive/Docs — через backend и серверный OAuth. RUTUBE — встроенный плеер; собственные видео и аудио — защищённый файловый/object store. Caddy либо согласованный reverse proxy.

В каждом окружении одна основная PostgreSQL БД, разделённая логическими схемами:

1. `identity`: сотрудники, роли, подразделения, должности, иерархия, область полномочий;
2. `content`: статьи Базы знаний и курса, типизированные материалы (видео, аудио, тест, Google Docs), редакции статей БЗ, внешние источники и файлы;
3. `learning`: курсы, разделы/элементы, кампании, назначения, прохождения, попытки;
4. `review`: задачи, оценки, замечания, ручные решения;
5. `integration`: Bitrix/Google интеграции, очереди, статусы доставки и курсоры синхронизации;
6. `audit`: append-only след действий.

В MVP логическая область `knowledge` содержит дерево папок, размещение статей, разрешения папок и статей. Однократный импорт из листа «Каталог документов» создаёт папки и статьи со встроенными Google Docs/Sheets, после чего структуру ведут в RTM. Разметка утверждена в ADR-094.

## Владение контентом

**Статьи:** отдельные сущности; создаются в курсе или Базе знаний. Курс владеет внутренней статьёй без пользовательских редакций; База знаний содержит статью в одной папке с датированными редакциями. **Материалы:** `video`, `audio`, `test`, `google_document`, связанные с блоками статьи либо с курсом/редакцией теста. Независимое копирование статьи/теста создаёт новые UUID. **Google Docs:** актуальный источник внутри статьи, исторический текстовый снимок в редакции БЗ. **Курс:** живые разделы и элементы; завершённые результаты не пересчитываются.

## Контракт API и безопасности

- Авторизация: Bitrix24 → backend проверяет личность и создаёт защищённую серверную сессию. Роль и права определяются сервером по локальной базе с учётом Bitrix admin.
- Учебные операции строго transactional: публикация редакции статьи, изменение ACL, активация курса, запуск кампании/назначения, запись попытки, решение проверки, изменение лимита/дедлайна.
- Back-end проверяет право на конкретный курс/кампанию/сотрудника, а не только общий `role >= teacher`.
- Область данных и пагинация применяются **до** получения строк/подсчётов, экспорта, а не фильтруются только в браузере.
- API не раскрывает скрытые правильные ответы теста, секреты OAuth, персональные ответы чужих сотрудников.
- Все важные операции идемпотентны, учитывают повторные нажатия и конкурентные изменения (`row_version`/compare-and-set + unique keys).

## Фоновый worker

В отдельном процессе выполняются: синхронизация Bitrix24 сотрудников/департаментов/должностей/админов, чтение Google Docs (в пределах связанного аккаунта), напоминания, контроль дедлайнов, создание Bitrix уведомлений/задач, повторная отправка и аудит неудачной доставки. Backend сначала сохраняет кампанию + назначения + задачи на отправку атомарно, затем возвращает результат сохранения; worker отправляет сообщения с контролируемыми retry/backoff. Нельзя отображать «уведомление доставлено», пока поставщик не подтвердил. При перезапуске worker забирает зависшие задания по TTL, не дублируя назначение.

## Снапшоты и проверяемость истории

Дата пользовательского интерфейса `DD.MM.YYYY`, в БД `DATE`. Время `timestamptz` UTC. Исторические снимки, завершённые результаты и задания неизменны; текущий курс свободно редактируется; ручные действия оставляют автора. При публикации редакции статьи БЗ сохраняется компактный извлечённый текст каждого встроенного Google Docs, источник, время и хеш. Текущая статья показывает актуальный Google Docs; историческая редакция показывает датированный снимок.

Подтверждение кнопкой означает зарегистрированное действие внутри RTM, а **не** юридически квалифицированную электронную подпись. «Посмотрел видео» не доказывается надёжно одним событием открытия плеера.

## Среды и выпуск

`/opt/rtm-app` и его volumes/БД/таймеры — старый production, не трогать. Next — выделенный Compose-проект, БД, volumes, secrets, сеть и (после решения) каталоги и домен; возможная директория `/opt/rtm-education-next` — предложение. После отдельного пользовательского разрешения на commit/tag/push в `main` запускается автоматическое обновление Next, Alembic и проверки. Никаких прямых правок исходного кода на production. На этапе разработки пустые/тестовые данные без scheduled backup; перед реальным использованием — резервирование БД **и** файлов с восстановлением.

## Мониторинг и качество

Health/readiness, логи API/worker, состояние очереди и интеграций, уведомления об ошибках, лог миграций; pytest (backend), Vitest (компоненты), Playwright (роли/полные сценарии). Нельзя заменять браузерную проверку скриншотом или успешной сборкой. Утверждённые требования и точные кейсы — `QUALITY_AND_TEST_MATRIX.md`.

## Изменение живого курса

Backend проверяет право и конкурентную версию записи, атомарно сохраняет текущее содержание и аудит. Техническая версия optimistic locking не является пользовательской редакцией курса. Незавершившие получают актуальное содержание при следующем открытии; исторические попытки и завершённые результаты читаются по снимку фактически показанного. Google Docs разрешается по источнику в актуальный текст внутри статьи; прошлое подтверждение остаётся привязанным к редакции статьи БЗ.

## Приоритет окончательного согласования 23.11.2026

Курс и внутренние статьи/тесты не имеют пользовательских редакций; изменения разрешены при активных и завершённых кампаниях. Кампании курсов ссылаются на постоянные ID; обновлений — на редакцию статьи БЗ. Тест проходит по X/Y правильных автоматических ответов; свободные ответы принимаются или отклоняются без числовой оценки. Баллы начисляются только как награда после итогового «Сдан». Преподаватель работает с любым сотрудником компании, контент редактирует редактор и выше.
