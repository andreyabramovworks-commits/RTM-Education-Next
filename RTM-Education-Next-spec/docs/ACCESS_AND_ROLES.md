# Права доступа, сотрудники и область ответственности

## Источник личности и оргструктуры

Bitrix24 — источник учётной записи сотрудника (поставщик ID, ФИО, фото, email, должность/позиция, признак активности, департаменты, отношения вложенности, Bitrix-admin), RTM хранит стабильный внутренний UUID и свои роли, назначения, ответы/оценки, журналы. Синхронизация через backend + worker; инактивация не удаляет результаты. Поддерживать сотрудников в нескольких отделах. Должностной каталог нужен для будущей матрицы доступа.

## Утверждённые роли

| Роль | Наследование | Функции |
|---|---|---|
| Пользователь | — | Видит собственные назначенные курсы/кампании и доступный личный каталог БЗ, проходит, получает результаты; не видит админку и общую библиотеку. |
| Преподаватель | Пользователь | Ограниченная админка, просмотр назначений, людей, аналитики и попыток; проверяет ответы, отправляет напоминания и др. для любого сотрудника компании; **контент не создаёт/изменяет/удаляет**. |
| Редактор | Преподаватель | Полная рабочая админка: создавать и редактировать курсы, внутренние статьи/тесты и кампании; не назначает и не снимает системные роли. |
| Администратор | Редактор | Назначает роли, управляет опубликованными редакциями, имеет повышенные права; Bitrix24-admin автоматически admin RTM. |
| Разработчик | Администратор | Полный доступ, защищённые инструменты и безопасный предпросмотр от роли. Роль не получается автоматически из Bitrix24. |

**Сервер** всегда заново определяет роль/permissions; UI видимость кнопки не является доказательством права. Audit любых административных и исключительных действий.

При входе открывается пользовательская часть; кнопка «Админка» видна только при эффективной роли teacher/editor/admin/developer. Проверенный Bitrix24 ID `36` на портале `rtm-group.bitrix24.ru` закреплён за разработчиком Андреем Абрамовым и получает защищённый developer. Роль developer не выдаётся через интерфейс назначения ролей. Остальные локальные повышенные роли выдаются администратором; правило автоматического admin для Bitrix24-admin сохраняется.

## Действия преподавателя — утверждённый набор

- Просмотр назначенных ответов и попыток, критериев оценки, исходных версий и истории.
- Взять свободный ответ в работу; оценить каждый вопрос, дать комментарий, принять/вернуть в одном из двух режимов.
- Напоминание, изменение срока для конкретного назначения, дополнительные попытки, освобождение, ручной зачёт с причиной.
- Контекстная главная кнопка + меню **«Все действия»**: доступны все разрешённые операции, а не только одна по статусу. Недоступные показывать с пояснением.
- Повышенно рискованные операции требуют подтверждения, причины и отдельного audit. Backend проверяет роль и конкретный объект операции.

Преподаватель и выше может назначать обучение любому сотруднику компании, проверять ответы и попытки, напоминать, менять сроки, выдавать попытки, освобождать и подтверждать вручную. Существенные операции требуют причины, подтверждения и аудита. Backend проверяет роль.

## Будущие ACL Базы знаний

В MVP доступ к папке или отдельной статье Базы знаний назначается отделу, подотделу либо сотруднику. Разрешение папки наследуется всеми нынешними и будущими вложениями. Прямое разрешение статьи открывает цепочку папок, но не соседние статьи; запрещающих исключений нет. Backend проверяет листинг, поиск, прямые ссылки, редакции и медиапотоки. Статья курса не наследует ACL Базы знаний. Формат исходной таблицы для однократного импорта Google Docs уточняется в `OPEN-042`.

## Проверки

- Учитель не может сохранить редактор статьи/теста (UI + 403 backend).
- Просмотр или экспорт ответов разрешён преподавателю и выше для любого сотрудника; сервер проверяет роль и журналирует доступ.
- Изменение роли не даёт возможности повысить себя до developer; Bitrix admin отрабатывает корректно.
- Сотрудник уволен/деактивирован: доступ отозван, результаты остаются.
- Действия с данными другого сотрудника протоколируются, включая actor и объект.

## Запуск курсовых назначений, уточнение 23.11.2026

Преподаватель и выше может создать назначение активированного курса или опубликованной редакции статьи БЗ любому сотруднику компании. Это не даёт права редактировать курс, статью или тест. Backend проверяет роль, цель, получателей и действие. Редактор и выше редактирует контент и активирует курс. Удаление опубликованной редакции статьи БЗ — admin/developer.
