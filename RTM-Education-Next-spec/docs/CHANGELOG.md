# Журнал изменений спецификации

## 26.11.2026 — уточнение исправлений и награды теста

- Пользователь разрешил несколько исправлений свободного ответа до принятия и выбрал настраиваемые баллы за тест с однократным начислением. Безопасная реализационная настройка: на каждый возврат отдельный срок исправления по умолчанию 7 суток, исходный таймер не перезапускается.
- Закрыты OPEN-005 и OPEN-041; добавлены ADR-091/092, REQ-177/178 переведены в APPROVED, QA-137/138. Обновлены baseline, тестовый контракт, модель данных, валидатор и манифест. Остались другие вопросы OPEN.

## 25.11.2026 — устранение конфликта навигации перед реализацией

- По уточнению пользователя: после входа стартует пользовательская часть, админка открывается кнопкой только для teacher+; проверенный Bitrix24 ID 36 закреплён как developer. Добавлены ADR-090, REQ-205, QA-136; обновлены baseline, роли и навигация.

- `REQ-173` помечен `SUPERSEDED`: прежняя формулировка о четырёх пользовательских разделах противоречила позднему утверждённому `REQ-195` и `CURRENT_MVP_BASELINE.md`. Шесть административных разделов сохраняются. Источник — сверка комплекта перед реализацией по запросу пользователя.

## 0.7 — 25.11.2026 — статьи Базы знаний в MVP

- По ответам пользователя 1–13 заменена модель Google Docs как самостоятельного объекта ознакомления: редакции относятся к целой статье Базы знаний; актуальный Google Docs встроен в статью, исторический снимок хранится компактным извлечённым текстом.
- Полная База знаний со статьями, едиными папками, обложками, ACL по папке/статье и серверным видео/аудио включена в MVP. Google Docs из исходной таблицы импортируется однократно; затем структура поддерживается в RTM.
- Пользовательское меню: «Обучение → Курсы/Обновления», «База знаний», «Профиль». В курсе Google Docs и медиа вставляются в статью, а не становятся отдельными элементами программы.
- `materials` ограничена типами video/audio/test/google_document; `articles` выделена отдельно. Полный тест создаётся из мастера редакции и независимо копируется в следующую.
- Обновлены baseline, ADR-079–089, REQ-194–204, закрыты вопросы о снимке/ACL, добавлены QA-125–135, обновлены модель данных, ERD, UX, навигация и валидатор.
- Остались открытыми формат исходной таблицы для импорта, реальные Google OAuth-возможности и прочие вопросы в `OPEN_QUESTIONS.md`.

## 0.6 — 23.11.2026 — консолидация

- Полностью восстановлен набор решений из доступной беседы и документации v0.5 с разделением approved/proposed/open/superseded.
- Отменён нормативный раздел «Материалы» и схема канонического переиспользуемого материала во многих курсах для **статей/тестов**; введено владение курсом и независимое копирование с новыми UUID.
- Административные «Видеотека» и «База знаний» объединены в **одну** «Базу знаний», с отдельными областями документов и видео. В пользовательском представлении — только разрешённое содержимое.
- Google Docs добавляются в курсы через **выбор из Базы знаний**, не вводом ссылки в редакторе курса; зависимость от минимального реестра документов в MVP вынесена в OPEN-001.
- Зафиксированы разделы/секции курса, DnD внутри/между секциями, полноэкранные редакторы статьи/теста, in-app preview Google Docs/видео и сохранение контекста возврата.
- Добавлены подробные поля, действия, мастера назначений, роли, проверки тестов, будущие папки/права, критерии приёмки и сквозная трассировка.
- Исправлен дрейф предыдущей документации: четыре вкладки Центра проверок — **исторический факт о legacy**, не Next; отдельная «Материалы» — отменено; «Видеотека» как отдельная админ-вкладка — отменено.
- Добавлен проверяющий скрипт `scripts/validate_spec.py`, он проверяет структуру, ссылки, идентификаторы, контрольные требования и целостность архива отдельно.
- Прямой кодовый доступ к production **не разрешён**; автодеплой из main только после разрешённого push.

## 0.5 — 19.11.2026 — предыдущая спецификация (исторический источник)

Утверждены три вкладки Центра проверок, два режима возврата свободного ответа, основное действие плюс «Все действия», база тестов, worker и стек. Концепция отдельной библиотеки материалов тогда была предложением и **позже отклонена**. Исходный комплект сохранён как отдельный артефакт беседы; не переносить его устаревшие формулировки обратно.
